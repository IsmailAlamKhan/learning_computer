# Authoring brief: write or rewrite a module in the cards format

> All 20 modules are already in the cards format. This brief is the authoring guide for new or reworked modules; read "old format" / "legacy" below as historical (the old format no longer exists in the code). Format reference: [LESSON_SCHEMA.md](LESSON_SCHEMA.md).

Read first: `PROJECT_BRIEF.md` ("UX RULES (mandatory)"), `docs/UX_CONTRACT.md` (data model, text budget, tokens, **"Deck engine, UI and authoring guide"** — unit checklist and visual guidance), `docs/AUTHORING_BRIEF.md` (older rules on accuracy, Bengali quality, religion-neutral wording — still valid), and the REFERENCE lesson `src/content/lessons/m02.ts` + `src/content/glossary/m02.ts` + its e2e `e2e/module2*.spec.ts` and `e2e/helpers.ts`. Look at the finished look in `docs/screenshots/after-pilot/` (open the PNGs). The learner is an 18-year-old Gen-Z Bengali girl who will NOT read paragraphs.

Work only inside the worktree `/Volumes/OtherStuff/Development/personal-projects/for-borsha/learning_computer_ux` (branch `ux/readability-overhaul`; never touch the sibling folder `learning_computer`; do not run git; do not use `git stash`). Re-read a shared file right before editing; shared files (engine, sim, ui, other modules' files) are off-limits except tiny backward-compatible edits you must report.

## What to deliver for your module NN
1. **Rewrite `src/content/lessons/mNN.ts`** from the old format (current file, `LegacyLesson`) to the new `Lesson { units }` format (import `Lesson` from engine/types now). This is a REWRITE with the "didi" voice (friendly older sister, "আপনি", concrete, a little humour, Bangladesh-flavoured examples such as Facebook/Messenger/YouTube/bKash/online class/university or job forms where natural, never stiff, never baby-talk, religion-neutral). Do not merely truncate: decide the ONE idea per card, then write it fresh. **Technical accuracy must be preserved exactly** (shortcuts, menu names, paths, commands, outputs) — the old file is the technical source of truth; where an old long paragraph holds important detail that doesn't fit, put it in `learnMoreBn` (opens in a sheet) or a later card.
2. **Structure**: split the module into as many units as needed so that each unit is a short lesson: hook + 3–6 authored cards + guided steps (≤ ~15 per OS, hard max 22) + exactly 3 quiz questions + ≤3 recap chips. Old modules had 15–50 steps → usually 2–4 units. Unit ids stable and unique; step ids unique across the module (you may reuse old ids). Give every unit a short Bengali `titleBn`.
3. **Cards**: every card has a visual (kinds in `types.ts`; art/mock names ONLY from `src/ui/illustrations/names.ts`; mock `highlight` must be a listed region; view `/#/demo/art` to see what exists). Old widgets stay as "পারেন?" challenge moments: a card with `visual: { kind: 'widget', widget: '<id>' }` and a one-line textBn (widget ids = files in `src/content/widgets/`; keep them, do not rewrite widgets except trivial text trims). Use `demo` visuals for gestures, `mock` + `highlight` for "where on screen", `compare` for Windows vs Mac / before-after, `flow` for sequences, `code` for annotated code (≤6 lines, notes per line, optional output lines or browserPreview). Put a quick win (an interactive widget/demo or a trivial first click) within the first three cards/first step.
4. **Text budget** (hard failures in `scripts/audit-core.ts`): card text ≤ 35 words (aim ≤ 25), ≤ 2 sentences, ≤ 2 `**bold**` words, ≤ 3 chips of ≤ 4 words; step instruction ≤ 14 (aim ≤ 12, one action, starts with a verb); hint ≤ 18 (aim ≤ 15); success ≤ 8 (aim ≤ 6); step title ≤ 7 words; quiz question ≤ 24 (aim ≤ 20), option ≤ 10 (aim ≤ 8), explanation ≤ 18 (aim ≤ 15); recap items ≤ 9 words; real-world tasks ≤ 18 words (2–3 per module; `windowsTasksBn`/`macTasksBn` allowed). Glossary: one line ≤ 22 words (aim ≤ 18).
5. **Steps**: keep each step's `target` and `expectedAction` semantics exactly (they drive the engine and your e2e); rewrite only `titleBn`, `explanationBn` (the coach line), `hintBn`, `successMessageBn`, `simplerBn`. Drop `continue`-only tour steps (cards replace them) unless a step needs an acknowledgement. Use `inputVariant: 'mouse' | 'touchpad'` on cards/steps only where the pointing device changes the action (right-click, scroll, zoom, drag); the learner's device is auto-detected — never ask her. Quiz questions must be valid for both OSes and both devices (OS-neutral wording).
6. **Glossary**: rewrite `src/content/glossary/mNN.ts` entries: `meaningBn` one short line, add `icon` (one emoji) or `art` (an ArtName); keep ids.
7. **Module-level**: `realWorld` (2–3 short safe tasks), `teacherTipBn` (hidden behind a toggle; may stay informative), `minutes`, `glossaryIds`, `certificatePart` if the old file had it.
8. **E2E**: rewrite the module's Playwright spec(s) `e2e/mNN.spec.ts` (and any other spec that exercises your module's old UI, e.g. widget tests) for the new flow with the helpers in `e2e/helpers.ts` (you may append new helpers at the END of that file; don't change existing ones): walk EVERY guided step of every unit on Windows and Mac (+ the touchpad variant when you used `inputVariant`), the 3 quiz questions per unit (jump to the quiz with the seeded-progress trick or answer them), widgets render, completion. Module-specific unit tests (`src/content/__tests__/mNN*.test.ts`, widget tests) that referenced the old structure must be updated.
9. **Verify**: `npx tsc -b`; `npx vitest run` (full suite; legacy modules of others may still exist); `npx tsx scripts/audit-content.ts --allow-legacy 2>&1 | grep "mNN"` must show no violation for your module (look at the tight ones too and improve); your e2e with your own port: `PW_PORT=<port> PW_OUTDIR=/tmp/dist-mNN PW_CHANNEL=chrome npx playwright test e2e/mNN.spec.ts`. Then LOOK at your work: start `npx vite --port <port+1000>` (or preview the build) and screenshot with a throwaway Playwright script (in /tmp) at least 8 representative cards/steps/quiz screens at 1440×900 and 390×844 (see `scripts/shots-after-pilot.mjs` for how the pilot did it — copy that pattern, don't edit it); Read the PNGs; fix overflow, empty-looking cards, unclear visuals, anything text-heavy; iterate until it looks good. Save final screenshots into `docs/screenshots/after/mNN-<n>-<1440|390>.png`.
10. **Report** (short): units/cards/steps counts, what you cut or moved into learn-more, any engine/UI/art gaps you hit (e.g. missing illustration you wanted), tiny shared edits you made, Bengali phrases a native speaker should double-check.
