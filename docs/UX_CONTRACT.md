# UX overhaul contract (read with PROJECT_BRIEF.md "UX RULES")

Work happens in the git worktree `../learning_computer_ux` on branch `ux/readability-overhaul` (the original folder has someone else's uncommitted work — never touch it). Dev/test commands run inside this worktree. Don't run git; the lead commits.

## Data model (src/engine/types.ts)
`Lesson { units: Unit[] }`; `Unit { hook: Card, cards: Card[] (3–6), steps: Step[], setup?, checklist?, quiz (exactly 3), recapBn (≤3), freeTryBn? }`; `Card { type: hook|visual|compare|code, textBn, visual: Visual, chipsBn?, learnMoreBn?, osVariant?, inputVariant? }`.
`Visual` kinds: art, flow, compare, mock, demo, code, widget, big (see types.ts). Names for art/mocks: src/ui/illustrations/names.ts. All 20 modules use this format; the old explanation/sections format has been removed.
Input devices: steps/cards may be `inputVariant: 'mouse' | 'touchpad' | 'both'`; the learner's device is auto-detected (profile.input) so touchpad-only content is never shown to a mouse user and vice versa.

## Text budget (enforced by `npm run audit:content`)
Card text ≤25 words (hard 35), ≤2 sentences, ≤2 bold words (`**word**`), ≤3 chips, ≤3 recap items (≤8 words each). Step instruction ≤12 words, one action, starts with a verb; hint ≤15; success ≤6. Quiz question ≤20 words, option ≤8, explanation ≤15. Longer detail → `learnMoreBn`. Glossary meaning ≤18 words (one line).

## Voice ("didi")
Friendly older-sister mentor, "আপনি" consistently (warmth through word choice: "চলুন", "দেখুন তো", "একদম সোজা!", a tiny joke at times), concrete and Bangladesh-flavoured (Facebook, Messenger, YouTube, bKash, online class, university/job form). Never stiff, never baby-talk. Religion-neutral (never নমস্কার/সালাম/আদাব/প্রণাম). Technical accuracy must be preserved exactly (shortcuts, menus, commands, paths).

## Deck engine, UI and authoring guide (DECK task)

**Code map.** `src/engine/deck.ts` (pure: `buildSlides`, navigation reducer, `keyIntent`, `swipeIntent`, save/restore helpers, `splitIfLong`) · `src/pages/DeckPage.tsx` (units overview → one unit at a time) · `src/ui/cards/*` (CardSlide, CardVisual/FitBox, PracticeSlide, QuizSlide, CelebrateSlide, UnitsOverview, Sheet, `deck.css`) · `src/ui/quiz/DeckQuestions.tsx` (the five question types as big answer cards). `ModulePage` loads the lesson and shows `DeckPage` (or the "coming soon / locked" screen). A sample lesson with every card kind and quiz type lives at `/#/demo/deck` (`src/pages/demo/deckSample.ts`, stored under module 99 — not part of the course).

**What a learner sees.** Slides: `hook` → `card` × n → `practice` (only if the unit has steps for her OS/pointing device) → `quiz` × 3 (one question per screen) → `celebrate`. Practice and quiz slides are gated (the big button stays disabled until done; going back is always possible; replaying a finished unit has no gates). Keys: Space/Enter/→ next, ← back, Esc closes (an open sheet first); inside the simulated computer or a text field the keys belong to that widget; on practice/quiz slides only Esc is a shortcut. Swipe left/right (touch/pen, ≥ 60 px) on hook/card slides. Position is saved per unit in `extras['deck:<module>:<unit>'] = {index, wrong?}`; a half-finished unit offers "আগের জায়গা থেকে চালিয়ে যাবেন?". The OS chip in the header toggles Windows/Mac content (default: `profile.os`); cards and steps are filtered by `osVariant` and by the learner's pointing device (`profile.input`; a touchscreen counts as touchpad).

**Progress written by the deck.** steps: `markStepDone(module, os, stepId)` + `addXp(XP.step)` (once per step); quiz: `recordUnitQuiz(module, unitId, {score, total, wrongByQuestion})` after the 3rd right answer (score = first-try-correct); celebration: `completeUnit` (first time only), then if every unit is done `completeModule` + `addXp(XP.moduleDone)` (+ `addCertificate(certificatePart)`; badges `part1` / `part2` for modules 13 / 20). The teacher dashboard (`src/lib/teacher.ts`) merges `unitQuiz` across units (scores/totals added, retries = all wrong attempts), counts steps per OS for the learner's pointing device, and lists weak questions from every unit.

### Writing a Unit — checklist
1. **Hook** (`type: 'hook'`): one relatable line (≤ 15 words), often a phone/Facebook/bKash analogy. It is spoken by the mentor "didi" in a speech bubble; give it a visual too (compare, art, flow…).
2. **3–6 cards** (authored count — OS/input variants count!). One idea each, ≤ 25 words, ≤ 2 `**bold**` words, ≤ 3 chips (≤ 4 words), extra detail in `learnMoreBn` (opens in a sheet). Per learner a unit should still show ≥ 3 cards for every OS/input combination (content test checks).
3. **Steps**: `osVariant` is required (`'both'` when identical), add `inputVariant` only where the gesture differs (right-click: `rc-mouse` / `rc-pad`). ≤ 12 words, start with a verb, hint ≤ 15, success ≤ 6. Keep ids stable and unique across the module. First practice step = a trivial click (the "quick win"); a `demo` card before it counts too.
4. **Exactly 3 quiz questions**, all valid for both OSes (no OS-only questions — write OS-neutral wording like "স্টার্ট (Windows) বা লঞ্চপ্যাড (Mac)"). Mix types over the module (at least one clickTarget, one dragMatch). `hintBn` is shown after a wrong answer (gentle), `explanationBn` after the right one.
5. `recapBn` ≤ 3 chips ≤ 8 words; optional `freeTryBn`; optional `checklist` (ticks when its steps are done); `setup` for the starting state of the sim.
6. A unit with more than 12 deck items must be split (`splitIfLong(unit)` / `splitWarnings(lesson)` in `deck.ts`; content test enforces it).

### Choosing visuals — what fits on a card
The visual area is whatever height is left between the header and the text (≈ 480 px on a laptop, ≈ 380 px on a phone) and is **scaled to fit**, never scrolled: `art`/`flow`/`big` are enlarged up to 1.6×, `mock`/`demo`/`compare`/`code` fill the width (max ≈ 720 px) and shrink if too tall. Prefer: **art** for an analogy (one object), **flow** for 2–4 steps (input → process → output; ≤ 4 items, short labels), **compare** for Windows vs Mac / before-after / right-wrong (two short labels; stacks vertically < 520 px), **mock** with a `highlight` region when the point is "where is it on screen", **demo** for gestures (click, double-click, right-click, two-finger-tap, drag, scroll, type, keys), **code** for ≤ 6 short lines with notes (no horizontal scrolling), **widget** only for a real "পারেন?" moment (it scrolls inside its own area and is the one visual allowed to be taller than the card). Don't add a second visual idea in the text.

### E2E helpers
`e2e/helpers.ts` documents `openModule`, `startUnit`, `nextCard`, `skipToPractice`, `expectPracticeDone`, `expectNoScroll`, the quiz helpers (`answerChoice`, `answerClick`, `matchPairs`, `orderItems`, `predict`, `checkAnswer`, `expectWrong`, `expectRight`) and `seedProfile(page, os, { input, modules, extras })` (pins the pointing device so auto-detection cannot change it). Reference specs: `e2e/module2*.spec.ts`, `e2e/deck.spec.ts`. Tip: jump straight to the quiz by seeding `extras: {'deck:<m>:<unit>': {index: <first quiz slide>}}` and `startUnit(page, i, 'continue')`.
